## 🤝 Кодекс поведения

При участии в проекте ожидаем соблюдения следующих принципов:

- **Уважение**: Будьте вежливы и уважительны к другим участникам
- **Инклюзивность**: Проект открыт для всех независимо от опыта
- **Конструктивность**: Предлагайте решения, а не только критику
- **Законность**: Не нарушайте права интеллектуальной собственности

**Запрещено:**
- Использование торговых марок "Harry Potter" в коммерческих целях
- Добавление защищенного авторским правом контента (изображения, музыка из фильмов)
- Оскорбления, дискриминация или токсичное поведение

## 🚀 Как внести свой вклад

### Для начинающих

1. **Найдите задачу**: Посмотрите Issues с меткой `good first issue`
2. **Форкните репозиторий**: Нажмите кнопку "Fork" на GitHub
3. **Клонируйте локально**: 
   ```bash
   git clone https://github.com/ВАШ_ЮЗЕРНЕЙМ/chess-online.git
   cd chess-online
   ```
4. **Создайте ветку**:
   ```bash
   git checkout -b feature/ваша-фича
   ```

### Типы вклада

Мы принимаем различные виды вклада:

- 🐛 Исправление багов
- ✨ Новые функции
- 📝 Улучшение документации
- 🎨 Улучшение дизайна/UI
- 🌍 Переводы на другие языки
- 🧪 Тесты
- 💡 Предложения по оптимизации

## 💻 Требования к коду

### Стандарты кода

**JavaScript:**
```javascript
// ✅ Хорошо
function getValidMoves(row, col) {
    const moves = [];
    // логика...
    return moves;
}

// ❌ Избегайте
function f(r,c){let m=[];/*...*/return m;}
```

**CSS:**
```css
/* ✅ Хорошо */
.square.valid-move::after {
    content: '';
    position: absolute;
    width: 20px;
}

/* ❌ Избегайте inline-стилей в HTML */
```

### Стиль кода

- Используйте понятные имена переменных на английском языке
- Добавляйте комментарии для сложной логики
- Следуйте принципам DRY (Don't Repeat Yourself)
- Максимальная длина строки: 100 символов

### Структура файлов

```
chess-game/
├── index.html          # Основной файл (HTML + CSS + JS)
└── ...другие файлы...
```

Если добавляете новые файлы:
- Размещайте их в соответствующих директориях
- Используйте lowercase имена файлов
- Добавляйте комментарии в начале файла

## 🔀 Процесс Pull Request

### Шаг 1: Подготовка

```bash
# Обновите главную ветку
git checkout main
git pull origin main

# Создайте новую ветку
git checkout -b feature/описание-изменений
```

### Шаг 2: Внесите изменения

- Делайте атомарные коммиты (одно изменение = один коммит)
- Пишите понятные сообщения коммитов

**Формат сообщения коммита:**
```
type: краткое описание

[опционально: подробное описание]

Fixes #123  [если исправляет issue]
```

**Типы коммитов:**
- `feat`: Новая функция
- `fix`: Исправление бага
- `docs`: Изменения документации
- `style`: Форматирование кода
- `refactor`: Рефакторинг
- `test`: Добавление тестов
- `chore`: Изменения сборки, зависимости

**Примеры:**
```bash
git commit -m "feat: добавить настройку сложности ИИ"
git commit -m "fix: исправить баг с рокировкой"
git commit -m "docs: обновить README.md"
```

### Шаг 3: Отправьте изменения

```bash
git push origin feature/описание-изменений
```

### Шаг 4: Создайте Pull Request

1. Перейдите на страницу вашего форка на GitHub
2. Нажмите "Pull requests" → "New pull request"
3. Выберите вашу ветку
4. Заполните шаблон PR

### Шаблон Pull Request

```markdown
## Описание изменений
<!-- Опишите что изменилось и зачем -->

## Тип изменений
- [ ] Багфикс
- [ ] Новая функция
- [ ] Улучшение существующей функции
- [ ] Документация
- [ ] Другое

## Связанные Issues
<!-- Укажите номера связанных issues -->
Closes #123

## Чеклист
- [ ] Код следует стандартам проекта
- [ ] Добавлены комментарии (где необходимо)
- [ ] Протестировано локально
- [ ] Документация обновлена (если нужно)
- [ ] Нет нарушений авторских прав

## Скриншоты (если применимо)
<!-- Добавьте скриншоты изменений UI -->

## Дополнительная информация
<!-- Любая другая полезная информация -->
```

### Шаг 5: Code Review

- Будьте готовы к комментариям и правкам
- Отвечайте на замечания конструктивно
- Вносите необходимые изменения

### Шаг 6: Merge

После одобрения ваш PR будет объединен с основной веткой.

## 🐛 Отчет об ошибках

### Перед созданием отчета

1. Проверьте существующие Issues - возможно баг уже известен
2. Убедитесь, что используете последнюю версию
3. Проверьте, воспроизводится ли баг в разных браузерах

### Шаблон отчета об ошибке

```markdown
**Описание ошибки**
Четкое описание проблемы

**Как воспроизвести**
Шаги для воспроизведения:
1. Открыть '...'
2. Нажать '....'
3. Увидеть ошибку

**Ожидаемое поведение**
Что должно было произойти

**Скриншоты**
Если применимо, добавьте скриншоты

**Окружение:**
- ОС: [Windows/Mac/Linux]
- Браузер: [Chrome/Firefox/Safari]
- Версия: [например, 91.0]

**Дополнительный контекст**
Любая другая информация
```

## ⚖️ Юридические аспекты вклада

### При внесении кода вы подтверждаете:

1. **Оригинальность**: Код написан вами или имеет совместимую лицензию
2. **Лицензирование**: Вы согласны лицензировать свой вклад под MIT
3. **Отсутствие нарушений**: Код не нарушает чужих авторских прав
4. **Нет торговых марок**: Не используются защищенные торговые марки

### Что нельзя добавлять:

- ❌ Изображения из фильмов о Гарри Поттере
- ❌ Музыку из саундтреков
- ❌ Логотипы Warner Bros. или других правообладателей
- ❌ Код с лицензиями, несовместимыми с MIT (GPL, AGPL и т.д.)

### Что можно добавлять:

- ✅ Оригинальный код
- ✅ Код с лицензиями MIT, BSD, Apache 2.0
- ✅ SVG-графику собственного производства
- ✅ Шрифты с открытой лицензией
- ✅ Библиотеки с совместимыми лицензиями
